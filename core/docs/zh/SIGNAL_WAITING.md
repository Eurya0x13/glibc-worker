# 信号掩码与等待

[English](../en/SIGNAL_WAITING.md) | [简体中文](../zh/SIGNAL_WAITING.md)

本契约适用于显式启用 native-unwind 服务中的活跃收养 Guest 调用，必须使用匹配 libc。
它保护 Host 保留信号；完整 Guest 异步投递仍未完成。

## 接口行为

收养 Guest 拥有逻辑掩码，暂停的 Host 保留自己的掩码。
Host 保留信号的物理内核掩码采用 Host 位，因此 Guest 修改既不能解除 Host 的屏蔽，
也不能压制未屏蔽的 VM 信号。其余位遵循已有 Guest 掩码适配；原始系统调用绕过它。

| 接口 | 适配 |
| --- | --- |
| `sigsuspend`、`ppoll`、`pselect`、`epoll_pwait`、`epoll_pwait2` | 翻译临时执行掩码，保留暂停 Host 的保留信号位。 |
| `sigtimedwait`、`sigwaitinfo`、`sigwait` | 从可消费集合排除 Host 保留信号；后两者保留原生委托到 `sigtimedwait` 的路径。 |
| `sigpending` | 从 Guest 查询结果隐藏 Host 保留信号，不改变内核队列。 |
| `signalfd` | 创建或更新 Guest 描述符掩码时排除 Host 保留信号。 |

可消费集合不是执行掩码，将 Host 掩码位复制进去反而会授权消费 Host 信号。
只含保留编号的集合变为空集，定时等待保留原生超时/错误行为。
该机制不取出并重造信号：Host 实时信号的负载、发送者信息及 FIFO 顺序留在内核。

跨域传入的已有 Host signalfd 仍使用 Host 创建的掩码。适配器不接管任意描述符，
描述符共享规则仍由调用者定义。

## 掩码事务

`wait-mask.inc` 在屏蔽可捕获信号后保存物理/逻辑掩码，发布临时 Guest 逻辑掩码，
再构造物理系统调用参数，由所属 libc 的已有系统调用原子安装并等待。
正常及错误返回都恢复原有两种掩码，并保留返回值/errno。
如果只修改系统调用参数，Guest 处理器看到的逻辑掩码仍会是旧值。

TLS 中没有指向自动事务记录的指针，因此非局部跳出不会遗留指向该失效栈帧的指针。
所选跳转/上下文接口的掩码语义仍由原生保存/恢复适配决定。
Host 目标跳转通过桥展开协调，不执行被放弃等待包装的正常尾声。

NULL 临时掩码与未绑定 GNU pthread 保留原生路径，包括取消行为。
补丁保留 glibc 的取消包装和超时代码。已审阅路径为 x86_64/AArch64 上的 LP64 time64，
不宣称 time32 已验证。

## 验证与边界

内部 `signal_router_defer_faults` 试点将保留故障信号的执行位与 Host 掩码分开，
只有显式 JNI `--host-fault-mask` 用例启用。六个未使用的实时信号归运行时所有，
对其注册返回 `EBUSY`。原始 siginfo 保存在按需分配的接收者队列中。Host 掩码、查询和
消费等待拦截负责转换通知位，保留原生内部信号过滤和取消入口。bionic 解析底层
`sigprocmask64`、`sigtimedwait64`，避免公开别名之间递归。
Host 的 `sigsuspend`、`ppoll`、`pselect`、`epoll_pwait`、`epoll_pwait2`
也转换临时掩码，包含 bionic LP64 别名；NULL 掩码保持原生路径。汇编将内核处理器入口的
实际掩码与 `ucontext.uc_sigmask` 分别保存：Linux 的掩码等待在后者保存等待前掩码，供
返回时恢复。已路由 Host 处理器看到逻辑上下文掩码，有效修改在返回时转换回物理掩码。

显式 Host 启动目标还适配 `signalfd`/Android `signalfd64`、`read`/`__read_chk`、
`readv`、`dup`、`dup2`、`dup3` 及 `fcntl`/`fcntl64` 的复制命令。
内核 signalfd 的通知位与创建线程无关，消费使用读取线程自己的接收者队列。
普通内核记录逐字节保持不变；通知转换为 128 字节的 `signalfd_siginfo`，保留原始
来源码、PID、UID 及联合体字段。向量读取保留当前内核的布局规则：新内核允许一条
记录跨多个 iovec，已测 Android 5.4 内核则在消费前返回 `EINVAL`。原生读取保留
阻塞、非阻塞、部分读取和取消行为，不保留隐藏描述符。复制描述符共享内核 OFD 掩码
和状态标记。

`poll`、`select`、`epoll_wait` 及掩码等待接口在检查就绪前，清理本接收者已撤销的
通知电平，不丢弃仍存活的原始信号。显式信道启用时，公开读取检查
`/proc/thread-self/fd` 及 `fdinfo` 中的实际 signalfd 掩码；私有 FD 表必须使用
`thread-self`。不再缓存数字 FD，也没有需要在关闭/替换后退休的元数据租约。
复制、SCM_RIGHTS 导入、原始 close 和 `close_range` 因而保留实际 OFD 语义。
所有者仍须串行化替换与活跃读取。检查使用原始、非取消系统调用，期间屏蔽可捕获信号，
不分配内存，并在恢复投递前关闭临时 proc 描述符。stdio 内部读取仍须接入；
原始读取及私有 libc 句柄会绕过公开适配。
原生信号与延迟通知通道之间的逻辑出队顺序也未完成；混合记录用例检查元数据，
不能证明信号选择优先级等价。原生元数据对照不代替这项证明。

链接公开原生跳转拦截目标并完成 `gw_nonlocal_init()` 后，受管读取与消费等待还负责
系统调用到解码之间的所有权窗口。信号入口在执行 Host 处理器前，记录内核已经消费的
私有通知，对应原始信号不再处于逻辑待决状态。处理器新发送的信号拥有独立所有权，
即使旧通知只是已撤销的电平也如此。当前被选中执行的通知处理器保留自身投递的所有权；
嵌套读取不会窃取外层结果。正常返回解码暂存记录，跳向外部的 `siglongjmp` 在普通 Host
栈上清理它，pthread 取消使用所属 libc 的清理入口。已消费的原生输出被丢弃，
处理器新发送的信号保持存活。有活跃消费边界时，存活上下文退休返回 `EBUSY`。

生产调用仍经过原生 libc 的读取/等待取消点。复制失败保留原生出队行为，零 iovec
读取保留原生返回零的行为。测试在原生操作完成、解码开始前注入信号，覆盖嵌套读取、
处理器内部跳转、跳向外部、已撤销通知及选中的通知处理器。桌面另检查消费后的取消；
bionic 没有公开 pthread 取消接口。这些不覆盖 Host `setcontext` 或可恢复的保存上下文。
未初始化跳转拦截时使用普通解码路径，不宣称该路径已具备完整窗口恢复能力。

`close` 保留原生取消点，不再持有元数据事务、写锁、取消禁用状态或隐藏副本。
跳转/取消不会遗留数字 FD 记录，也不会误删替代描述符。生命周期检查读取所有活跃线程
的实际表，包括私有 `files_struct`；线程退出与批量关闭不需要用户态退休钩子。
启用/恢复时仍要求描述符所有者静止。proc 检查不可用时返回 `ENOTSUP`，不猜测表已为空。
原生关闭窗口与取消回归仍保留。这不证明原生消费期间任意 `setcontext` 退出已受支持。

成功的 Host `SIG_IGN` 注册推进不可变的丢弃代数。接收者在展示或消费逻辑待决队列前
应用它；恢复处理器不会让旧待决信号复活。注册线程不遍历其他线程的 TLS，也不访问其
可能正在退休的队列。已经消费的记录保留自身所有权：已发送但不再待决的通知属于读取
操作或已选中的处理器，不属于需要丢弃的待决队列。忽略期间的新发送直接丢弃。
64 轮屏障控制用例交替使用原生及延迟待决输入，由另一线程设置忽略并恢复旧动作，
随后检查新发送；还验证忽略变更前已消费的读取/等待结果保持有效。这不证明辅助通知
选择、Host 注册与一次性动作消费的所有并发关系已等价，相关 disposition 竞争仍须接入。
公开掩码变更、原生跳转恢复及 Guest 返回 Host 的命令路径，都会在解屏蔽前清理失效
电平。用例还在不先查询待决状态、不先读取记录的情况下，检查解屏蔽及保存掩码跳转。
逻辑动作是 `SIG_IGN` 时，真实 Host 同步故障仍保留原生致命语义，外层路由不能让被
忽略的硬件故障无限重试。原生及路由两组独立子进程都必须由 `SIGSEGV` 终止，不能由
用例超时信号终止。Host 忽略该编号期间的独立 Guest 陷阱恢复，由已安装 JNI 用例检查。

原生关闭可能在包装器返回前释放编号。内核对象检查防止替代描述符中类似通知的
字节被误解码。检查失败返回 `ENOTSUP`，不消费数据。额外 proc 系统调用仅在显式
延迟信道启用时发生；这是正确性修改，不宣称性能提升。

启用信道时，任何已有 Host signalfd（包括未记录的描述符）都会使其返回 `EBUSY`。
恢复路由时检查实际掩码是否仍包含私有通知，包含导入描述符及其他线程私有表中的 OFD。
空掩码不再持有通知编号。全表扫描只在串行生命周期边界运行，不是常规读取的注册表遍历。
五项用例覆盖原始复制、SCM_RIGHTS、批量关闭、私有表保留及启用前未记录的描述符。
内核或策略限制报告 `UNAVAILABLE`，不计为正向覆盖；缺少 `close_range` 时，私有表用例
尝试 `unshare(CLONE_FILES)`。

延迟处理器选择、对应的不可变 Host 动作及一次性动作消费，均在注册写事务中确定。
运行应用代码前结束事务。路由的一次性动作在暴露处理器掩码前耗尽，因此嵌套投递看到
默认动作。屏障控制的原生/延迟用例在进入应用处理器前替换已选动作，包括中间设置忽略，
要求保留已选代数。每个辅助通知的内核入口还绑定不可变 Host 代数及其 `SA_RESTART`。
在并发忽略/替换前已被内核选中的通知保留旧代数；新代数不能使被忽略作废的记录复活。
四项对照先观察真实阻塞的管道读取，再分别投递启用/禁用重启的原生及延迟记录。
延迟记录由受控用例发送者在选择锁内发布，不是新增的公开跨线程队列 API。
修复前启用重启的延迟用例错误返回 `EINTR`。首次内核安装后发生失败时，回滚动作，
并将可能已被选中的记录保留至静止回收。原生/延迟出队优先级等价仍未完成。
新接收者发布后还会重新应用逻辑掩码，避免初始私有屏蔽状态使第一个信号长期无法投递。

有待决工作时，存活线程释放上下文会在释放 Guest 状态前返回 `EBUSY`，消费或解屏蔽后
可重试。真正的线程退出只排空自身私有通知、丢弃自身待决工作。还有活跃延迟接收者时，
拒绝恢复外层路由。接收者全部退出后，由启用线程恢复路由及其原有的私有通知掩码位，
保留其他 Host 掩码修改；后续路由生命周期不得沿用这份私有掩码。
这不证明通用保存 continuation 已经静止。

在工作区根目录执行 `python3 core/tests/signal_deferred.py`，Android ARM64 追加
`--ndk /path/to/ndk --serial DEVICE`。它验证真实故障、合并元数据、内核等待/signalfd
通知、撤销后的新发送、通知失败后重试及接收者退出。原生 libc 对照还检查临时、NULL、
阻塞等待掩码、上下文掩码修改、超时参数不变，以及处理器中保存/不保存掩码的跳转。
桌面执行五种等待接口；Android 执行八个公开或 LP64 入口，两个不可用的
`epoll_pwait2` 入口以 `ENOSYS` 跳过。Host 描述符覆盖对五种 siginfo 布局与原始内核
signalfd 作完整记录对照，并检查普通/延迟混合记录、原生向量布局、别名掩码更新、描述符
替换、六种就绪接口、撤销通知及另一读取线程。底层队列用例仍显式解码原始私有通知。
四组阻塞用例还将普通/向量读取与原始内核创建的描述符对照，检查 `EINTR`；
先观察实际阻塞的系统调用，再发送中断。桌面另有四组 pthread 取消用例。bionic
没有公开 `pthread_cancel` API，Android 明确报告不可用，不算通过。每条实际执行的
路径均要求接收者清理完成。
并发 disposition 修改和上述描述符接入缺口仍未完成，不能将此试点当成通用异步投递启用。

[SDK 用例](../../../android-jni/docs/zh/SDK_TESTS.md) 检查 19 组等待，以及两次从实际观察到的
内核 `rt_sigsuspend` 等待跳回 Host，之后检查再次 JNI 调用、用例自有资源清理、模块关闭和
运行时退出。缺少 `epoll_pwait2` 会报告跳过。桌面环境实际执行该调用；已测 Android ARM64
JRE17 shell 环境返回 `ENOSYS`，跳过两项。错误返回的掩码恢复已检查，成功等待路径仍需支持它的
内核验证。这不证明 APK 沙盒或 ART 已验证。

Guest 逻辑队列、标记发送、GNU pthread 上的 Host 投递、通用保存 continuation 生命周期，
以及未测别名/窗口仍是必须完成的工作。上述防护保护已有 Host 队列，不宣称剩余机制完成。
