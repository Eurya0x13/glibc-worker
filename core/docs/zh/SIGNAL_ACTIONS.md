# Guest 信号处置

[English](../en/SIGNAL_ACTIONS.md) | [简体中文](../zh/SIGNAL_ACTIONS.md)

`signal-actions.h` 将逻辑处置与[目标注册表](SIGNAL_TARGETS.md)连接。
安装的 C 源码必须由所属 libc 编译。每次操作前物理屏蔽可捕获信号；
写锁顺序为处置表、目标表、inbox。释放全部写锁后才能调用应用处理器。

## 选择与替换

表为 Linux LP64 的每个信号编号保留一个条目。每次成功注册获得经过溢出检查、
单调递增的 revision；耗尽返回 `EOVERFLOW`，保留原处置。
无效编号返回 `EINVAL`，配置的注册保留编号返回 `EBUSY`。

选择操作将完整处置和 revision 复制到调用者自己的存储中。
`SA_RESETHAND` 在同一事务中将当前处理器改成 `SIG_DFL`，保留其标志和掩码；
并发接收者不可能同时选择这个一次性处理器。
后续替换不影响已选择的快照，也不分配待回收的注册记录。

保存的原生 continuation 自己持有快照存储的生命周期。
本表既不能证明暂停的信号帧已失效，也不会替无效的原生模块卸载固定应用处理器代码。
目标、栈和模块仍须遵守各自的所有权规则。

## 发送与忽略

`change` 在发布新处置前，清除所有私有和共享队列中即将被忽略的编号。
这包括默认忽略的 `SIGCHLD`、`SIGURG`、`SIGWINCH` 和 `SIGCONT`。
后续发送、处置修改和投递选择共享处置表外层事务，发送者无法在清队列与发布之间
重新填入被忽略的信号。该行为参照 Linux 的
[忽略处置清理](https://github.com/torvalds/linux/blob/v6.12/kernel/signal.c)。

忽略发送仍验证目标身份和异步保留编号。目标屏蔽该编号时，Linux 仍保留消息，
也会考虑临时等待保存的 `real_blocked` 掩码；只有未屏蔽的忽略发送不消耗配额。
失效的定向目标返回 `ESRCH`；忽略保留编号不能绕过 `EBUSY`。
注册和异步发送可以使用不同的保留掩码，使执行域的硬件故障与 Host 所有的异步通道共存。

`gw_signal_actions_representative` 在进程发送前显式固定逻辑线程组首领。
其掩码控制 Linux 的进程发送忽略过滤，不能由随后选中的可投递接收者代替。
线程退出后仍固定该身份，直到处置所有者关闭。未配置的进程发送返回 `ENOTSUP`。
`gw_signal_target_masks` 在目标写锁内发布当前掩码和等待保存的掩码。

`deliver` 在同一事务中选择消息及其处置。
目标注册表的线程队列优先于共享队列顺序、实时信号配额记账均保持不变。
已接受发布和通知失败仍由不同结果字段表达。
清队列后残留的内核通知必须走隐藏通知路径，不能虚构应用投递。

## 接入与验证

已安装的 JNI Guest 使用这套快照处理六种同步故障和独立异步信号。
传入空目标表时启用同步故障接口。
已安装的 Guest 服务将停止、继续及待决队列更新交给
[Linux 作业控制](SIGNAL_WAITING.md#共享-linux-作业控制)。

`core/tests/signal_actions.c` 覆盖快照替换、注册参数别名、一次性处置竞争、
忽略清队列、配额恢复、保留编号、revision 耗尽、屏蔽的忽略信号、首领生命周期，
以及四发送者与注册修改并发。同一测试内的独立原生 libc 对照复现普通、实时和
默认忽略编号在屏蔽时仍待决、可由消费等待取出的行为。
它通过原生 Host/core CTest、Clang UBSan，并由 `core/tests/guest_async.py`
在 Linux 和 Android ARM64 上作为所属 GNU libc 的对照执行。

过滤发送还会在忽略判定前清除全部队列中相反的停止/继续待决信号，符合 Linux
生成时顺序。原生对照验证两个方向。服务接入路径由内核执行进程停止、恢复
以及相应的待决队列更新。
