# Guest 信号目标注册表

[English](../en/SIGNAL_TARGETS.md) | [简体中文](../zh/SIGNAL_TARGETS.md)

clone 前的 `prepare` 预留身份，但不能通知或消费消息；不分配内存的 `activate`
在创建返回前启用真实 TID。顺序、失败及创建者/子线程 pin 规则见
[创建阶段和所有权](THREAD_LIFECYCLE.md)。向量中的预备成员尚不具备投递资格。

`signal-targets.h` 将独立 inbox 接到真实接收者的准入、逻辑掩码、通知和退休。
与[信号 inbox](GUEST_SIGNAL_INBOX.md)一样，必须用所属 libc 编译安装的 C 源码。
不能在 Guest TLS 下调用 Host 编译的实现。

## 身份与发布

每个目标持有稳定 receiver、所属 libc 的不透明线程键、内核 TID 和集成上下文。
开放寻址索引处理定向发送；紧密的活动向量选择进程消息接收者。两者都检查容量
运算并动态增长。关闭会移除活动成员，但不移动稳定目标。libc 描述符地址复用
时创建新的目标身份；旧身份的 pin 不能消费新目标的消息。

注册表 writer 包围 inbox 事务及非阻塞通知回调。每次调用前都须物理屏蔽可捕获
信号；所属 libc 的发送 hook 已建立此条件。回调不能调用注册表、分配或等待
接收者。发布与关闭因此有统一顺序：close 返回后，后来的发送不能再通知该目标。
TID 不匹配返回 `ESRCH`；线程信号零只探测，不入队。定向线程键必须来自 libc
已经验证的描述符路径，不能使用未保护的缓存 `pthread_t`。

真实目标只能在 TCB 绑定、入口栈/状态就绪、外层内核路由可以找到它之后准入。
准入会检查既有共享消息。共享发送选择当前合格的活动接收者；所有接收者都
阻塞时保留待决消息。目标解除阻塞时重新检查私有及共享待决状态。选择继续遵循
inbox 的 Linux 私有队列优先及各编号顺序规则。

`gw_signal_targets_send` 与 `gw_signal_target_mask` 分别返回 `status` 和
`wake_error`。非零 status 表示没有发送或修改掩码；wake error 表示发布或掩码
修改已经提交，不能把它当作未发送而重新发布。查询 `gw_signal_targets_error`，
然后用 `gw_signal_targets_retry` 重试通知，或在集成边界隔离运行时。新目标准入
成功后的首次通知失败也不会撤销注册，注册表错误状态会保留此失败。

## 消费等待与处置变更

`gw_signal_target_take` 按显式 eligibility 掩码选择信号，不修改目标逻辑掩码。
与处理器投递不同，它能消费已屏蔽信号，供信号等待适配器使用。线程定向 pending
仍先于共享 pending，两者保留 inbox 的各编号顺序。这只是非阻塞队列操作，
不实现内核等待、超时、应用指针写回或通知消费。

`gw_signal_targets_discard` 在注册表 writer 内，从共享队列及每个活跃目标的
定向队列清除一个编号。它精确释放被清除的实时信号配额，保留其他编号及所有
掩码。底层 `gw_signal_inbox_discard` 提供对应的单队列操作。使用注册表持有
的目标时，不得绕过注册表直接修改 receiver。

处置所有者必须在其外层事务内完成清除、新动作发布及后续发送策略。仅清除
不会安装 `SIG_IGN`，也不会丢弃之后新发布的包。较早的内核通知仍可能进入而
没有可投递包，必须走隐藏/过期通知路径。已选中的处理器代次和保存帧继续遵守
各自生命周期。Linux 在
[do_sigaction](https://github.com/torvalds/linux/blob/v6.12/kernel/signal.c)
中处理忽略处置的 pending 清理；外层运行时仍需把该策略连接到这些队列操作。

## 入口与保存帧的生命周期

`gw_signal_target_pin` 仅在目标开放时准入新入口。已持有 pin 的入口可以通过
`gw_signal_target_retain` 派生保存延续的持有，即使新投递已撤销也可以。
`gw_signal_target_unpin` 释放两种持有。调用者必须跟踪所有保存延续及非局部跳转
退休的后缀；注册表不能由处理器计数为零推断未来不会 `setcontext` 恢复。

Close 丢弃该目标私有待决队列并撤销新发送/入口，保留既有 pin 使用的存储。
Release 要求已关闭、pin 为零，且所属集成已明确证明来源及帧静默；否则返回
`EBUSY`。最终销毁注册表要求先关闭并释放所有保留目标。Close 或失败的 release
都不会释放仍被持有的 TCB、栈或模块。

当前双 libc 夹具在真实 TCB 绑定及入口设置完成后注册接收者，为每次正常返回
的 Guest 入口持有 pin，并在物理通知排空、Guest finish 和载体 join 之后释放。
公开 libc 发送回调直接使用此注册表。小型固定载体数组仅控制测试预期的逻辑
掩码调度，不再用于运行时目标查找。

## 验证及剩余集成

原生控制测试扩到 2,048 个稳定目标，在旧身份仍有 pin 时复用描述符键，令四个
发送者与 close 竞争，并检查共享准入/解除阻塞。发布和掩码修改都注入已接受但
通知失败的场景。额外检查消费逻辑屏蔽的信号，清除私有/共享队列中的普通与实时
消息，回收耗尽的总配额，保留无关 FIFO 数值，拒绝非法/预留编号，并让四个
发送者与重复清除竞争；之后的新发布与投递仍须正常。控制测试使用 Linux 和
Android ARM64 上匹配的 GNU libc。Host/core 版本另有 Clang UBSan 检查。

这些是接收者/队列的生命周期保证。已安装的 JNI 服务仍需公开异步处置、完整
逻辑掩码/等待 hook，以及通用保存帧协调。正常返回的入口测试不构成任意异步
非局部退出或 VM 集成已完成的证明。

[处置表](SIGNAL_ACTIONS.md) 将处置替换、忽略清队列、发送和投递选择置于同一事务。
选中的处置复制到接收者持有的存储中。
